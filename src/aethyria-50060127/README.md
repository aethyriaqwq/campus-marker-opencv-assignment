# 校内赛标志物识别

个人目录是 `src/aethyria-50060127`。程序看每一帧里有没有这块发光标志。有，并且缺口就在画面里、方向只读得出一种、外沿也贴在亮边上，就给出图纸四角的投影，顺序是 `LT`、`RT`、`RB`、`LB`。四个角一起给。缺口还在画面外、方向不唯一，或者外沿没贴上，这一帧就是未检出：左上角一块深色底，上面写 `undetected`，上一帧的框清掉。画面字体没有中文，所以用这八个字母。

发光图案和估计用的数字分在两个文件里。改它们不用改程序。相机内参仍在 `camera.yaml`。

## 环境

Ubuntu 24.04.5，GCC 13.3.0，C++17，CMake 3.28.3，OpenCV 4.6.0。

```bash
sudo apt install build-essential cmake libopencv-dev
```

OpenCV 由 CMake 的 `find_package` 查找，不写安装路径。

## 编译

在仓库根目录执行：

```bash
cmake -S src/aethyria-50060127 -B build/aethyria-50060127 -DCMAKE_BUILD_TYPE=Release
cmake --build build/aethyria-50060127 --parallel
```

可执行文件是 `build/aethyria-50060127/marker_detect`。几何检查是 `build/aethyria-50060127/marker_geometry_test`，不使用 GTest。`build/` 不提交。

## 运行

在仓库根目录执行。不写 `--output-dir` 和 `--output-video` 时，只在终端打印统计。

```bash
build/aethyria-50060127/marker_detect --input data/raw/marker_video.avi
```

| 参数 | 作用 |
| --- | --- |
| `--input` | 要读的视频。帧率取容器元数据 |
| `--output-dir` | 把选中的帧写成 `frame_` 加四位帧号的 PNG。没写 `--save-every` 时每帧都写 |
| `--save-every` | 正整数间隔，从窗口第一帧算起，第一帧一定保存。必须和 `--output-dir` 一起用 |
| `--output-video` | 把选中的每一帧写成标注视频，编码 `avc1`，帧率取容器元数据。可以和 PNG 同时写 |
| `--from` | 闭区间起点，默认 0。更早的帧只为接上跨帧位姿而检测，不打印、不保存、不计入汇总 |
| `--to` | 闭区间终点。省略则读到视频结束。读完这一帧就停 |
| `--calibrate` | 用 `--input` 估计内参。只接受 `--input` 和 `--camera` |
| `--camera` | 标定 yaml。检测和标定都读它。默认 `src/aethyria-50060127/camera.yaml` |
| `--model` | 标志的几何。默认 `src/aethyria-50060127/marker.yaml` |
| `--params` | 估计用的数字。默认 `src/aethyria-50060127/detector.yaml` |
| `--help` | 打印用法 |

`--save-every` 小于 1、帧号为负、`--to` 早于 `--from`、未知参数、缺取值、整数没写完整、空的输入，都会失败并打印用法，退出码 2。`--calibrate` 再带上输出、窗口、`--model` 或 `--params` 同样失败。选中的范围是空的时，打印 `no frames in range`，退出码 1。

每隔 20 帧存一张：

```bash
build/aethyria-50060127/marker_detect \
  --input data/raw/marker_video.avi \
  --output-dir output/aethyria-50060127/frames \
  --save-every 20
```

终端按连续段打印 `detected 起-止 support N` 或 `undetected 起-止`。现在只要检出，支持数就是 4。汇总行是 `measured4`、`measured3`、`measured2`、`measured1`。上一帧的位姿加上刚走的一步，是这一帧收边的起点。对不上就清掉再重找，不把上一帧的角抄过来。

测试视频是 `data/raw/marker_video.avi`：1440×1080，1676 帧，约 23.8 秒。本机从容器读到的帧率是 70.4083（8801/125）。检出帧数和这一趟的耗时写在 `REPORT.md`。

标定视频 `data/raw/calibration_video.avi` 的内参在 `camera.yaml`。物体单位是圆心间距。板的模型仍用图纸单位，外沿为 80。

## 发光的是什么

图纸 `docs/assets/marker_dimensions.jpg` 标的是整数，程序不读那张图，也不在图上量像素。

发光的是一圈不完整的方框。外沿 80，框宽 8，中间开口 64。四个角都是同样大小的 L，臂长 30，臂宽 8。没有一大一小两只 L。左上、左下、右下是整块。右上是同一只 L 开了缺口：从外角沿每条臂走，先亮 14，再暗 8，再亮到 30。缺口里侧那截亮的还是这条臂，不是另一只小灯。

从外沿读，四条边是：

- 上边，从左到右：亮 30、暗 20、亮 8、暗 8、亮 14
- 右边，从上到下：亮 14、暗 8、亮 8、暗 20、亮 30
- 下边，从左到右：亮 30、暗 20、亮 30
- 左边，从上到下：亮 30、暗 20、亮 30

方向就是这条码。外框是正方形，转 90 度外形几乎一样，所以不能靠轮廓面积，也不能靠“哪只灯更大”。中心的准星和外壳倒角不是目标。

这些数在 `marker.yaml`。`notch_corner: 1` 表示缺口在右上。

## 怎么判

未知量是这块板的刚体位姿。图像上的位置由内参、畸变和这个位姿算出来。

轮廓只用来提议一块板可能在哪。画出去的四个角是外沿上的亮暗台阶，不是那条轮廓。

1. 灰度图上用多档固定阈值找亮轮廓。默认是 32、64、96、128、160、192、224。亮的灯和暗的灯不会落在同一档，所以不用整幅图一个阈值。轮廓收成六边形，太小的丢掉，靠得很近的只留面积大的那只。
2. 种子是四只 L 的外形，坐标用图纸上的真位置。三只整块 L 的臂长是 30。缺口 L 连在一起的那截臂长是 14，只此一只，所以它自己就能指出右上。每只轮廓对每只种子试各个顶点和两个绕向。对得上的用平面位姿（IPPE）求出一个起点。板心要在相机前方，四角绕序要是正面。这个起点不直接当结果。
3. 轮廓是亮斑的外缘，往往会大出几像素，所以这一步不要求一条边都读对。按“缺口在右上”来读，要比另外三个转角更好，而且亮暗对比够，才拿去收边。
4. 收边只沿外框的外法向走，找最近的一处“内侧更亮”。窗口是一个框宽。臂的内侧边缘在一个框宽之内，但是外侧更亮，符号相反，不会被选中。开口里侧和缺口内部的边不参与。
5. 一条边要有足够多的在画面里的样本找到这个台阶，而且多数落在 2 像素以内，才算测到了这条边。平面方板的位姿要三条这样的边。只测到一条边时，另外三个角是外推，不输出。
6. 三条边各自的贴合点还要横跨外沿的一半。短的一截定不住远端的角。已经贴在外沿上之后，某一条边滑出画面，只要剩下的边还锁得住、缺口也没读反，可以继续。
7. 方向要读到缺口本身。右上那两段暗 8，至少有一段落在画面里并且读成暗的，落在画面里的缺口段都要读对。缺口还在画面外时，外沿的法向残差定不住沿边的尺寸，边长不同的几个方框都能贴上看得见的边，这一帧不输出。四个朝向里只有这一种成立，才输出四个角。两个都贴上、边的代价又接近、四角还对不上，这一帧不输出。同一块板上留边代价更小的那个。外沿已经由“内侧更亮”选定，不因为方框更大就留下它。
8. 下一帧从上一帧的位姿加上刚走的一步开始收。外沿还锁着、缺口没读反，就用这个结果，并记下这一步。对不上就清掉旧位姿，整帧重找。重找同样要读到缺口。重找失败就是未检出，不把上一帧的角抄过来。

暗的参照点取在开口中心，不取在臂内侧一笔画的位置。灯有光晕，靠得太近的点两边都是亮的，整条亮边会被读成暗的。

`detector.yaml` 里和传感器有关的是像素：对比度至少 12 个灰度，台阶落在 2 像素以内算贴上，搜索至少 2 像素。和板子有关的用图纸单位或比例，不把这一支视频里的灯有多大量进程序。搜索宽度、一条边要盖住的比例，都在这个文件里，改它们不用改程序。

## 画面

四个角一起画。边先铺一层黑，再铺一层白，亮灯和暗背景上都看得清，用 `clipLine` 收到图像边界。落在画面里的角用同样大小的圆环，颜色和左上角的图例一致：`LT` 蓝、`RT` 黄、`RB` 红、`LB` 绿。名字不写在角上，写在左上角一块固定的深色底里，按板上的位置排成两行，所以不会叠到灯上，也不会一边字大一边字小。角在画面外时，图例里的色块是空心的，结果里仍保留这个投影。图例末行写着缺口在 `RT`。未检出时同一位置只留 `undetected`。
