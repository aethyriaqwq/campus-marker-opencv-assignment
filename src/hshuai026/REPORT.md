# REPORT：校内赛标志物识别

> 作者：帅蘅轩（学号 hshuai026）

## 1. 素材与目标特征观察

- 测试视频 `data/raw/marker_video.avi`：1440×1080、70.4 FPS、1676 帧，共约 23.8 秒。
- 标志物是暗背景上的白色灯组：多个高亮方块（角块约 74×74 px，另有中部小块），
  整体外框约 195×190 px。全画面高亮（V > 200）像素占比约 1.2%。
- 背景整体很暗：全图均值 BGR ≈ (47, 47, 47)，因此“高亮”比“颜色”更可靠。
- 目标离开画面时高亮像素占比降到约 0.17%，这对“未检测到”的判定很关键。
- 素材中标志物基本保持正向、只有平移和轻微缩放，没有明显旋转，因此外接旋转矩形
  足以描述目标，四点顺序在整段视频中保持稳定。

## 2. 方法流程

1. `cv::cvtColor` 转灰度 → `cv::threshold(gray, 200, 255)` 得到高亮掩膜。
2. `cv::morphologyEx(MORPH_OPEN, 3×3)` 去掉孤立噪点；`cv::dilate(51×51)`
   把分散的灯块合并为一个候选区域。
3. `cv::findContours(RETR_EXTERNAL)` 提取外轮廓，按面积、边长、长宽比、紧凑度筛选，
   取面积最大的候选。
4. 在候选区域内取原始高亮像素，`cv::convexHull` + `cv::minAreaRect` 得到旋转外框，
   再用 `cv::RotatedRect::points` 得到四个顶点，按“先分左右、再分上下”排序为
   LT / RT / RB / LB。
5. 跨帧：顶点做 EMA 平滑；连续丢失 ≤ 5 帧时沿用平滑结果（抑制闪烁），
   超过 5 帧立即输出“未检测到”并停止绘制。

### 为什么这样设计

- **用亮度而不是颜色**：灯面是白色、饱和度低，颜色阈值在曝光变化下不稳定；
  亮度阈值（200）在整段素材中都能把灯面和背景分开。
- **用膨胀合并而不是模板匹配**：标志物内部最宽的暗缝约 45 px，51×51 的核能把
  四个角块并成一个候选，避免了“同一目标被拆成多块”的问题，也不依赖先验模板。
- **用凸包 + 旋转矩形而不是水平外接框**：外框贴合灯面，目标轻微倾斜时四个顶点
  仍落在目标边界附近。
- **有限保持 + 立即清空**：既抑制单帧漏检造成的闪烁，又满足“目标离开画面时返回
  未检测到、不得无限复制上一帧结果”的要求。

## 3. 关键参数与依据

| 参数 | 取值 | 依据 |
| --- | --- | --- |
| 亮度阈值 | 200 | 灯面约 250、背景均值 < 60，取中间偏上的值 |
| 开运算核 | 3×3 | 只删除孤立噪点，不破坏灯块形状 |
| 膨胀核 | 51×51 | 大于标志物内部最大暗缝（约 45 px），保证合并成一整块 |
| 面积范围 | 1500 ~ 300000 px² | 覆盖 195×190 的目标及部分可见的情况 |
| 边长范围 | 80 ~ 900 px | 目标边长约 190 px，留出两倍以上余量 |
| 长宽比上限 | 2.0 | 目标接近正方形，排除细长干扰（灯带、支架） |
| 紧凑度下限 | 0.30 | 排除空心、细长的误检区域 |
| 丢失帧数 | 5 | 70 FPS 下约 0.07 秒，足以跨过单帧抖动 |
| EMA 系数 α | 0.35 | 兼顾平滑与跟踪滞后 |

## 4. 实测结果（全片 1676 帧）

- 单帧直接命中 **1256 / 1676 = 74.94%**；未命中的区间与目标离开画面完全对应。
- 逐段命中：帧 200–399、600–799、1000–1199 均为 200/200；帧 800–999 为 97/200、
  帧 1200–1399 为 55/200，对应目标出画的区段。
- 连续未检测区间（帧号）：46–116、431–461、860–962、1239–1383、1585–1654。
  抽查帧 450 / 900 / 1350 的高亮像素占比均为 0.169%（有目标时为 1.2%），
  说明这些区间确实是目标不在画面中，而不是漏检。
- 检测到目标时外框高度 186.9 ± 11.1 px、中心 y 419.3 ± 5.2 px（目标基本沿水平
  方向移动，纵向稳定）。
- 相邻检出帧的中心跳变：平均 7.9 px、最大 13.6 px（目标水平移动速度约 7 px/帧），
  没有出现跳框或闪烁。
- 全片处理耗时约 21 秒（含 MP4 编码），远快于实时。

## 5. 失败案例

1. **目标部分移出画面**（帧 825–860、1225）：外框宽度缩到 71~150 px。原因是算法只
   统计画面内的高亮像素；此时框仍然贴在可见部分上，但不再等于目标真实尺寸。
2. **目标刚进入画面**（帧 1650）：可见面积不足 `min_area`，判定为未检测，直到
   帧 1675 完整进入后才检出。属于阈值与“部分可见”取舍问题。
3. **快速横移时的轻微滞后**：EMA 平滑在目标快速移动时会让外框落后约 1~2 px，
   对验收无影响，但若追求更低滞后可改用卡尔曼滤波。

## 6. 改进思路

- 增加灯块之间的相对几何校验（角块 + 中部小块的固定间距），进一步压低误检；
- 用上一帧位置限制搜索 ROI，减少全图遍历并提高稳定性；
- 支持多目标输出（当前只保留面积最大的候选）；
- 对画面边缘目标用可见部分 + 对称性估计完整外框；
- 完成标定与 `solvePnP` 位姿估计（挑战部分），用 `docs/assets/marker_dimensions.jpg`
  的已知尺寸建立三维点。

## 7. 已知限制

- 参数按本素材整定，强光或白色背景场景需要重新标定阈值；
- 未做畸变校正，画面边缘的顶点存在少量畸变偏差；
- 只输出一个目标；
- 挑战部分的标定与位姿估计见第 8 节。

## 8. 挑战部分：相机标定与位姿估计

### 8.1 标定板与使用的帧

- **标定板类型**：黑色边框 + **7×7 对称圆点阵列**（不是棋盘格，所以用
  `cv::findCirclesGrid` + 斑点检测器识别，共 49 个圆点）。
- **点间距**：材料中没有给出实测值；标定程序里按 **30 mm** 记录（该值只影响
  平移尺度的解释，**不影响内参与畸变系数**，因为内参只由像素决定）。
- **使用的帧**：标定视频共 6966 帧。每 15 帧取一张（465 帧）中检出点阵 450 次；
  再按"清晰度（Laplacian 标准差）与点阵跨度均在中位数以上"筛选、相邻视角位移
  > 25 px 去重、均匀抽稀到 45 个视角；标定过程中按 2×RMS 剔除 5 个异常视角，
  最终使用 **40 个视角**（帧号记录在 `camera_calibration.yaml` 的 `used_frames`）。

### 8.2 内参与畸变系数的来源

全部由 `data/raw/calibration_video.avi` 用张正友标定法（`cv::calibrateCamera`，
固定 k3 的 4 参数畸变模型）解算得到，**不是从截图或相机参数推断**：

```text
fx = 2387.37 px    fy = 2386.48 px
cx =  704.36 px    cy =  564.48 px

k1 = -0.0602   k2 =  0.1487   p1 = -4.8e-05   p2 = -5.0e-04   (k3 固定为 0)
```

- 重投影误差：**RMS = 1.28 px**，平均 0.97 px，最差 3.70 px（图像 1440×1080）；
- 剔除的 5 个视角误差 > 3.8 px，主要来自运动模糊与点阵靠近画面边缘的帧；
- 采样策略（清晰度/跨度筛选 + 位移去重）把 RMS 从 3.03 px 降到 1.28 px。

### 8.3 坐标系定义与单位

| 坐标系 | 定义 |
| --- | --- |
| 标志物坐标系 | 原点在标志物**正面中心**；X 向右、Y 向下、Z 垂直正面**指向相机**；单位 **mm**。四个角点模型坐标为 (∓40, ∓40, 0)，即按图纸主视图 80×80 mm 外轮廓建模 |
| 相机坐标系 | OpenCV 约定：原点在光心，X 向右、Y 向下、Z 沿光轴向前；单位 mm |
| 图像坐标系 | 像素，原点在左上角，u 向右、v 向下；畸变由标定得到的 k1,k2,p1,p2 校正 |

位姿定义：`tvec` 是标志物原点在**相机坐标系**中的位置（mm），`rvec` 是标志物
坐标系到相机坐标系的旋转向量（罗德里格斯形式）。可视化里用
`cv::drawFrameAxes` 画出的三轴为 **红 = 标志物 X、绿 = 标志物 Y、蓝 = 标志物 Z**，
轴长 80 mm，因此画面里可以直接按轴长估算距离。

### 8.4 位姿结果、单位与稳定性

在 `data/raw/marker_video.avi`（1676 帧）上逐帧求解 `cv::solvePnP`（IPPE，平面靶标）：

| 指标 | 结果 |
| --- | --- |
| 成功帧数 | 检测 1256 / 1676（74.9%），其中给出位姿 1281 帧（含短暂遮挡期的预测帧） |
| 距离 | 平均 **1017.6 mm**，标准差 **18.0 mm**，范围 983.7 ~ 1062.7 mm |
| 位姿重投影误差 | 平均 **0.67 px**，最大 3.14 px |
| 输出 | `marker_video_result.mp4`（框 + 顶点 + 像素坐标 + 三轴 + 毫米数值）、`marker_video_result.csv`（像素与位姿同一份日志）、`overview_*.jpg` / `sequence_*.jpg` |

说明：**必做与选做共用同一套输出**——同一个视频、同一份日志里同时包含
"像素级检测结果"和"毫米级位姿结果"，不分成两批材料。

稳定性观察：目标在画面中清晰可见的连续片段里，距离估计波动在 ±20 mm 以内
（约 2%），位姿重投影误差稳定在 1 px 量级；目标离开画面时程序停止输出位姿，
与必做部分"未检测到"的状态一致，不会沿用过期结果。

### 8.5 挑战部分的失败案例与限制

1. **绝对尺度依赖图纸尺寸**：标志物按主视图 80×80 mm 外轮廓建模；若实际发光面
   比外壳小，距离会按同比例偏小（例如按 70 mm 建模时距离约 893 mm）。图纸未
   标注发光面相对外轮廓的内缩量，因此该误差无法进一步消除。
2. **标定点间距未实测**：内参与畸变不受影响，但报告中不能据此给出"标定板实际
   尺寸"的断言。
3. **运动模糊**：手持拍摄 + 70 fps，部分帧点阵/标志物边缘模糊，是重投影误差
   的主要来源；已通过清晰度筛选把影响降到 1 px 量级。
4. **平面靶标退化**：标志物视频里目标以正面为主、倾角有限，若画面长期只出现
   正面姿态，`solvePnP` 对绕 Z 轴旋转的解算会更敏感；本素材中未出现明显异常。

## 9. 时序滤波与运动滞后优化（快速运动时的"落后"问题）

### 9.1 问题定位

原实现在四个顶点上做 EMA 平滑（α = 0.35）。EMA 是一阶低通滤波器，等效时间常数
τ = (1−α)/α ≈ 1.86 帧；目标匀速运动时稳态滞后 ≈ v·τ。本素材目标速度约
7.9 px/帧，因此理论上落后约 13 px。用互相关对 1256 个检测点实测：
**滞后 2.0 帧**，与理论一致。目标越快，落后越多。

（说明：相机标定是静态参数，不存在"落后"；落后发生在每帧的检测/位姿输出环节。）

### 9.2 候选方案与实测对比

在 `marker_video.avi` 的全部**原始检测**轨迹（6 段、1256 个检测点，原始抖动基准
3.05 px）上离线评测，可用 `filter_eval` 复现（证据文件
`evidence/filter_comparison.csv`）。指标定义：**滞后**用互相关求（正 = 落后，
单位帧）；**抖动**为二阶差分标准差（px，越小越平滑）；**偏差 RMSE** 为滤波输出
与原始检测的差（px，越小越"贴"检测）。

| 方案 | 滞后(帧) | 抖动(px) | 偏差RMSE(px) | 评价 |
| --- | ---: | ---: | ---: | --- |
| EMA(α=0.35)（原方案） | 2.00 | 1.04 | 16.27 | 抖动最小，但快速运动落后 2 帧 |
| α-β(α=0.5, β=0.2) | 0.00 | 1.81 | 3.97 | 简单有效，噪声略大 |
| **KF-CV(q=0.5, r=9)（采用）** | **0.00** | 1.82 | **1.95** | 零滞后且最贴检测，综合最优 |
| One-Euro(0.6, 0.02, 1.0) | 0.00 | 2.37 | 1.77 | 零滞后、无需模型，抖动略大 |
| KF-CV + 前推 1 帧 | −0.83（提前） | 3.34 | 9.04 | 仅用于抵消流水线延迟 |
| KF-CV 强平滑(q=0.1, r=25) | 0.17 | 1.61 | 6.31 | 更平滑但更"钝"、跟踪变慢 |

### 9.3 采用的方案与动力学说明

- **采用 CV（匀速）卡尔曼滤波**（`tracking_filter.hpp`，状态 `[x, y, vx, vy]`），
  四个顶点各跑一路，**输出预测位置**，因此匀速段相位滞后 ≈ 0；
- **丢失帧用模型预测填充**（`advance()`），不再复制上一帧，短暂遮挡期间输出的是
  按运动模型外推的位置；
- **动力学升级路径**：若目标换成本队车辆（转弯、加减速），把 CV 换成
  **CA（匀加速）**或 **CTRV（匀速 + 转弯）**/自行车模型即可，用底盘角速度 ω
  作为控制输入；本素材是手持平移，CV 已经足够（用 CTRV 反而需要额外输入）；
- **延迟补偿取舍**：若整条流水线存在已知固定延迟 L，可把 `filter_predict_steps`
  设为 L。离线评测显示前推 1 帧会把"滞后 0"变成"提前 1 帧"，代价是偏差 RMSE
  从 1.57 px 升到 8.80 px——属于"用噪声换提前量"，只在确认有延迟时使用。

### 9.4 接入后的效果

| 项目 | 接入前 | 接入后 |
| --- | --- | --- |
| 必做部分顶点滞后 | 2.0 帧（约 13 px） | **0 帧** |
| 必做部分检测率 | 74.94% | 74.94%（不变，滤波不影响检出） |
| 位姿距离 | 1020.6 ± 17.5 mm | 1021.5 ± 17.7 mm（994.4 ~ 1062.9 mm） |
| 位姿重投影误差 | 平均 0.80 px | 平均 **0.77 px** |

选型建议：**追求精度用 KF-CV；想少写代码、又要低滞后，用 One-Euro；α-β 适合
资源受限的嵌入式实现。** 三者都能消除 EMA 的滞后问题，差别只在平滑与灵敏度的
权衡。

> 交付代码中的滤波实现（`tracking_filter.hpp`）单独做过一致性校验：
> 在同样的原始检测轨迹上实测 **滞后 = 0 帧、与检测的平均偏差 = 1.24 px、
> 平均二阶差分（抖动）= 1.18 px**，与上表 KF-CV 行一致。
> 校验时确实发现并修正了一处协方差预测（F P Fᵀ）展开写错的问题——修正前滤波器
> 会过度自信、跟随变慢，这也是"滤波后反而比原始检测更差"的根因。
